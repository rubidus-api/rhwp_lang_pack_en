feat(i18n): 언어팩 골격 (1/4)

문자열은 상태바 몇 개 외에 옮기지 않는다. 화면은 도입 전과 같다.

- src/i18n/: 조회·폴백(core), 로케일 결정(resolve), 마크업 적용(dom), 진입점(index)
- 기본 로케일은 ko, 폴백은 현재 로케일 → ko → 키. ko 카탈로그가 원문을 담으므로
  번역이 0% 여도 원문이 그대로 나온다
- 로케일은 ?lang= 이나 저장된 선택으로만 바뀐다. 브라우저 언어는 기본으로 보지 않는다 —
  고른 적 없는데 화면이 바뀌면 안 되고, CI 러너(en-US)에서 UI 가 저절로 영어가 되면
  레이아웃에 민감한 e2e 의 전제가 달라진다
- public/locale-init.js: 번들 전에 <html lang> 을 고른 로케일로 찍는다. theme-init.js 와
  같은 방식(동기 외부 스크립트 — 확장 CSP 가 인라인을 막는다). 이게 없으면 영어 사용자가
  첫 페인트에 한국어 도구 모음을 보고 번들이 뜬 뒤 바뀌는 깜빡임을 본다.
  resolve.ts 와 키·순서가 어긋나지 않도록 테스트로 묶었다
- main.ts: initI18n() 연결과, 상태 표시줄(구역·모드·파일 이름과 쪽수 메시지)·머리말/꼬리말
  표시를 런타임에 한국어로 다시 쓰던 12곳을 t() 로. 이게 없으면 2단계의 마크업 번역이
  첫 문서 로드 순간 사라진다
- 같은 표시를 함께 만드는 view/page-indicator(쪽 표시), engine/header-footer-mode
  (짝수 쪽/홀수 쪽/양쪽), view/canvas-view(머리말 배지)도 옮겨 영어 화면에서
  'Footer(짝수 쪽)' 처럼 섞이지 않게 했다
- t() 임포트는 @/ 별칭이 아니라 상대 경로다. 상류 테스트는 로더 없는 순수 node --test
  로 소스 모듈을 직접 import 하기도 하는데, 그 경로에는 별칭을 풀어 줄 것이 없다
- 언어 변경은 **다음 실행부터 적용**한다(#5852 검토 ①). setPreferredLocale() 은 선택을
  저장만 하고 { locale, appliesOnNextLaunch } 를 돌려준다. 즉시 전환은 열린 대화상자·
  모듈 상수·동적 메뉴·상태 표시줄을 현재 상태로 다시 만들어야 안전하므로 이 단계에서 하지 않는다
- 정적 마크업 적용은 요소가 아직 원문(초기 문구)을 보일 때만 바꾼다. 앱이 써 넣은
  현재 상태(구역: 2 / 3, 수정 모드, 바뀐 title)는 덮지 않는다 — 테스트로 고정
- 새 런타임 의존성 0, 순수 TypeScript
